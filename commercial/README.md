# PureISP 授权服务 1.1.9（客户端 1.1.3）

用户填入授权卡密并点击“启动”，无需注册、账号或密码。保留 v1.0.4 的本地 Mihomo、分流规则、IDE 启动和退出恢复。独立授权服务管理卡密、有效期及停用，不转发用户流量，无 Marzban 或 Redis 依赖。

## 本机试用

需要 Node.js 22 或更新版本，在 commercial 目录运行：

```powershell
npm ci
npm run setup
npm start
```

setup 生成 .env 和三个独立随机密钥；已有文件只在缺少 CARD_ENCRYPTION_KEY 时补入加密密钥，其余设置保留。默认 ACCOUNT_STORE=file，数据在 data/license-snapshot.json，不连接 MySQL。

1. 打开 http://127.0.0.1:3610/admin，从本机 .env 复制 ADMIN_KEY 进入管理。
2. 填备注和到期日期，生成卡密后交给用户；列表直接显示完整卡密，点击“续费 / 操作”栏中的“复制卡密”即可重新交付。
3. 复制一份完整的 v1.0.4 目录，将卡密更新包的三个文件放入复制目录。
4. 将 account-service.json 设置为下面的本机地址，再打开新 PureISP.exe。
5. 用户填卡密并点击“启动”；浏览器自动接入，IDE 从面板启动。

```json
{
  "serviceUrl": "http://127.0.0.1:3610",
  "renewalUrl": "http://127.0.0.1:3610/renew"
}
```

更新包不包含商业代理 YAML、住宅密码、Core 或 geoip，需要原完整客户端目录。旧 v1.0.4 和 v1.1.0 包保留。新版本使用独立卡密表和缓存，不迁移旧账号。

## 收费与续费

列表每条卡密用一行展示账号、完整卡密、状态、北京时间有效期和操作，复制按钮位于“续费 / 操作”栏。已停用的卡密排列在列表末尾，同状态组内保留原顺序；搜索、筛选及操作刷新后仍使用该顺序。搜索支持账号备注、完整卡密、尾号及卡密 ID（不区分大小写，也支持多个词），可叠加状态或“7 天内到期”筛选。搜索在已加载的数据中进行，不增加 MySQL 请求。续费、停用和刷新后保留筛选，生成新卡后清除筛选以显示新卡。卡密 ID 可在账号悬停提示中查看。

收款后生成卡密并交付。备注可留空，自动保存为“用户 + 六位随机数字”，例如“用户583921”；填写备注时沿用填写内容。后台点击“续费30天”或设置新日期，用户沿用同一卡密，再点“启动”同步。停用后服务器拒绝授权。本版没有自动支付和注册功能。

卡密为 128 位随机值；登录校验继续使用 SHA-256 摘要。新卡密同时使用 AES-256-GCM 加密存入原卡密表的 encrypted_key 字段（自动补充），磁盘快照同样只保存密文。登录管理后台后，列表直接显示完整卡密，“复制卡密”按钮位于“续费 / 操作”栏。通过一次管理员专用请求加载完整卡密；普通列表接口仍只返回尾号和是否保存完整卡密。用户登录接口不会返回密文或完整卡密。退出管理清除页面上的卡密。备注使用文本节点渲染。

CARD_ENCRYPTION_KEY 单独保存在服务端 .env 中，不交付客户端、不包含在发布 ZIP 中。备份数据库时也要单独妥善备份该密钥，迁移服务器须保留原值；不要随意重新生成，否则旧密文无法解密。完整卡密查看与登录校验相互独立，解密失败不改变有效期及卡密摘要。

升级前只存摘要的旧卡无法还原，页面显示“旧卡未保存完整卡密”。若有原始交付文件，可在停止本机授权服务后运行 `node --env-file=.env scripts/import-card.js "data/管理员卡密.txt"` 补入，再启动服务；导入只匹配已有摘要，不生成新用户、不修改有效期或启停状态。MySQL 模式还可等待运行中服务的下一次版本同步，但停止服务后导入能避免磁盘快照写入冲突。没有原始卡密时只能停用旧卡并生成新卡。

```powershell
npm run admin -- list
npm run admin -- reveal CARD_ID
npm run admin -- create "客户备注" 2026-12-01T00:00:00+08:00
npm run admin -- renew CARD_ID 2027-01-01T00:00:00+08:00
npm run admin -- disable CARD_ID
```

CARD_ID 来自列表，不是完整卡密。命令行日期须带时区；管理网页统一按北京时间（UTC+8）填写和显示，客户端显示北京时间及秒数，不随电脑时区改变。数据库原表仍保存 UTC，授权使用相同的实际时刻。生成命令的输出包含完整卡密，应保存用于交付。

本机数据库已添加 `pureisp_license_keys_beijing` 查看视图，`expires_at_beijing` 与界面时间一致，`expires_at_utc` 对应原表值。部署到其他数据库时可执行 `scripts/beijing-view.sql` 创建该视图，查看视图不改变任何卡密的期限。修改或续费仍通过管理后台；直接修改原表时填写 UTC（北京时间减 8 小时）。

## 服务器与 MySQL

服务器执行 npm ci 和 npm run setup，通过 HTTPS 反向代理转发到 127.0.0.1:3610，修改 .env 的 RENEWAL_URL 和客户端的两个 HTTPS 地址。客户端拒绝远程明文 HTTP；授权走直连，代理尚未启动也能验证。

同机反向代理时设置 TRUST_PROXY=true，代理覆盖 X-Forwarded-For 为真实客户端地址；服务只信任回环来源。卡密验证每个 IP 每分钟最多 20 次。管理接口需独立 ADMIN_KEY，用户不需要管理页面或 9090 控制台。

启动失败时，`npm start` 输出失败阶段和安全的错误提示，不输出数据库密码、连接串或 SQL。`CARD_ENCRYPTION_KEY` 必须是 64 位十六进制字符；`SESSION_SECRET` 和 `ADMIN_KEY` 各至少 64 位十六进制字符，三个密钥互不相同。`npm run setup` 保留已有 `.env`，复制模板后仍保留的 `CHANGE_ME` 不会被自动覆盖。检查已有密钥时不要删除 `.env` 或重新生成有效密钥。MySQL 的 `ER_ACCESS_DENIED_ERROR` 表示账号密码验证失败，`ER_SPECIFIC_ACCESS_DENIED_ERROR` 表示初始化权限不足，`ETIMEDOUT` 表示连接超时，需要检查 RDS 白名单和网络。

```dotenv
ACCOUNT_STORE=mysql
MYSQL_URL=mysql://USER:PASSWORD@RDS_HOST:3306/pureisp
MYSQL_SSL_CA=/path/to/rds-ca.pem
DB_POLL_SECONDS=10
```

URL 中账号密码特殊字符需编码，设置 CA 后校验 RDS 证书。优先使用服务器可访问的 RDS 内网地址。首次启动新建 pureisp_license_keys、pureisp_license_revision、pureisp_license_migrations 和三个触发器；升级时自动补入 encrypted_key 列，需要建表、改表及触发器权限，不改旧账号表或其他业务表。初始化失败且无有效快照时拒绝启动；已有快照可以恢复服务，数据库恢复后建议重启确认初始化。

用户请求读内存，不直接查 MySQL。连接池上限 3，每 10 秒查询一行版本号，变更才加载卡密表，每 24 小时完整核对一次。管理接口写库成功后立即更新内存。普通手工 SQL 修改触发版本更新，默认约 10 秒被服务发现，用户下次同步或点击“启动”得到修改。TRUNCATE、删除触发器或绕过触发器导入不属于此同步路径。

数据库故障保留上次内存和磁盘快照，既有卡密按原截止时间判断；生成、续费或停用等写入明确失败。故障期间不能发现尚未同步的修改。

## 客户端行为

- 打开面板只填充记住的卡密，点击“启动”才验证并运行代理。
- 首次必须联网；服务断线时，同一卡密可使用 DPAPI 保存的有效授权，换卡不能借用旧授权。
- 每 24 小时同步，本地每 30 秒检查截止时间，持续运行也会到期停止。
- 截止时间等于付费到期时间，不再赠送一天，重启、断网或刷新不延长。旧 EXPIRY_GRACE_SECONDS 配置已移除，新客户端也按付费到期时间限制旧缓存。
- 停用或无效响应清除会话；离线停用不能即时到达，最多使用到原缓存截止时间。
- 到期先恢复原系统网络设置，再停止自己的 Core，提示续费；卡密留在输入框，续费后点击“启动”。不强制关闭 IDE。
- 恢复失败保留 Core 与备份，提示通过“停止并退出”重试。
- 正常退出保留加密卡密；✕ 和最小化收进托盘，正常关机沿用原恢复逻辑。
- 卡密及会话由 DPAPI 加密。运行时用服务端时间加单调计时，离线发现明显回拨时要求联网验证。

轻量本地授权不能保证防破解或本地配置不可提取，修改客户端或直接运行配置可能绕过收费。强制拦截绕过需要代理入口校验。
